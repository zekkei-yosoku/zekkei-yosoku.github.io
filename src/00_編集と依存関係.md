# AstroNotesの編集正本と依存関係

`src/index.html` とそこから参照されるファイルを編集する。rootの `index.html` とtrialは生成物。直接編集しない。既存の天文/地形/codecなど `astronotes-*.js` は引き続きそれぞれの編集正本。ただし `astronotes-explore.js` は `src/features/explore/entry.inc` からの生成物。planning factory・layout adapter・controllerを同じ従来assetへ組み立てる。旧 `sorami-*` は凍結互換資産。

## 生成・検証

```sh
./bump.sh
python3 build-preview.py
node tools/build-index.mjs --check
python3 build-preview.py --check
python3 tools/run-ui-checks.py
```

bumpはsource組立→content version/preload/SRI→inline CSPをメモリ上で計算・構文検査してから、一回ずつ原子的に書き出す。--checkは組立だけでなくversion/CSPまで同じpure関数で再計算し、全byte一致を確認する。単にindexを上書きしてsourceと食い違わせた変更を検出する。trial生成は今まで通りrootから行う。

## なぜclassic inlineを維持するか

既存のlexical globalと初期化順は互換契約。機能/UIを変えない構造整理では、ESM/defer/asyncやCSS適用順の変更を同時に行わない。source fragmentsは同じscript内に元の順序で生成される。これは依存がすべて解消済みという意味ではない。scriptの公開global化や非同期読込への移行は別の検証が必要。

`source-manifest.json` のlegacyRuntimeOrderとgeneratedAssets.sourceOrderは実行順の台帳。factoryは新しいscript依存をHTMLへ足さず従来explore内へ同梱する。古いaccessがキャッシュに残った場合のfallbackも、正本のcanFrameから生成して同梱する。app/browser-state、app/navigation、app/overlaysは従来の共有状態/来た道/重ねる画面を担当する。featuresは画面別、servicesは通信/同期/検索、uiは地図/見え方/操作、startupは起動境界。関数の位置に依存する既存検査は生成済み配信物を引き続き検証する。

## 状態・互換境界

- `viewStateOwner` は8つの表示flagを、`accessGenerationOwner` は認証世代をそれぞれ単独で保持する。従来識別子はaccessor bridgeなので値の写し合いをしない。auth/token自体は従来のlexical変数のまま。初期化位置と代入/++の順序を変えない。

- 編集中の探す条件の正本はSkyMap session。sceneはそのsnapshotを投影する。別の計画台帳を作らない。
- `src/domain/planning/session.js` の `AstroNotesPlanningSession` はread portとscene jobの世代/keyを所有し、DOMや永続化を所有しない。
- `AstroNotesAccess.canFrame` は対象×天体のpolicy。本人確認/画面許可の呼出側guard、API認可は独立して維持する。
- 認証/同期のqueue/journal/保存キー、旧plan codec/catalog、画面ごとの日時の意味を変更しない。
- `src/features/explore/layout.js` が探すのmount/unmountとDOM復元情報を単独所有する。constructorはDOM/callbackへ触れず、controllerはgetterで状態を読む。旧aim/DOMの移動はcompatの接着として残る。source分割やjob抽出を、すべてのglobal/DOM所有が解消したという報告にしない。

## 変更時の確認

新しいsourceを足したらmanifestを同じ順序に更新する。結合した全classic scriptのlexical衝突検査はbuild時に行う。init前に状態を読む追加、feature間DOM書込、未解放listener/timer/observerをレビューする。既存のUI/権限/保存/競合/browser検証を実行し、文字列固定testを削除して通さない。UI/CSSの変更は構造整理と別diffで扱う。

## 副作用の所有と依存検査（2026-10-30）

- `ports/storage.js` はJSON読書きと成功後の通知hook、`ports/auth-storage.js` はsession/localの優先と保存順、`ports/http-client.js` はfetch・認証世代・401応答を扱う。accountのauth/tokenは従来のlexical正本へgetterで接続する。通知hookを二重に追加しない。
- `domain/navigation/routes.js` の純粋parserは `AstroNotesNavigationRoutes`。既存の航空データ `AstroNotesRoutes` と別の識別子を使う。`domain/navigation/history.js` は明示portを受けるhistory owner（manifest layerはports）、`app/navigation.js` は既存画面への接続とapplyRouteを担当。
- `services/account-sync.js` はflight/再実行と同期処理を所有し、`features/account/sync-bridge.js` が既存状態・RecordSync・画面のportを渡す。controller.incは認証・account・管理・import等の順序入口。constructorはIOを行わず最初の呼出時に生成する。
- `domain/scene/appearance.js` は空色・縁方向・輪郭描画の契約。`ui/scene/renderer.inc` はappearance接続とterrain/lens/silhouette/render/input/reverseを元の順序で組む。canvas命令・数式・イベント順は変更しない。

`source-manifest.json` のarchitectureが各JS単位のlayer/scope/provides/requires、9つのaccessor bridge、互換入口、既存global object参照を記録する。`tools/check-architecture.mjs` はbuild時に実ファイルと台帳を照合し、未分類・依存循環・未登録bridge/adapter・外部providerとのnamespace衝突・factoryの禁止ambient参照を拒否する。台帳の参照元と撤去条件も更新する。字句検査は一般JavaScriptパーサーやsecurity sandboxではないため、隔離VM・旧新trace・実ブラウザ検査を併用する。

新旧比較は `test-port-contracts.mjs` / `test-navigation-contract.mjs` / `test-sync-contract.mjs` / `test-scene-appearance-contract.mjs`、境界gateの負例は `test-architecture-contract.mjs`。基準commit97356e2をローカル履歴に保持する。classic composition内のUI共有lexicalは維持しており、全面ESM化やすべてのglobal解消を完了条件としない。

## データ保護の通し検査

`tools/test-data-safety.cjs` は実ブラウザで起動・受信・☆登録・送信失敗と再送・送信待ちの保護・削除・バックアップを確かめる。内部名に触れず、画面・保存・通信だけを見る。保存/同期/起動順に触れる変更では必ず実行する（ローカル配信のURLを `DATA_SAFETY_BASE` に指定）。`node --test`には含まれない。

`tools/test-account-safety.cjs` は別の人のログイン（データを渡さない）、初回の持込み、同じ人の再ログイン、ログアウト、予定・観測・撮影地点の送受信を確かめる（`ACCOUNT_SAFETY_BASE`）。ログイン/同期に触れる変更では両方実行する。

## 依存の明示（import / export 行）

classic-composition の各unitは、先頭の `import {名前} from '相対path';`（参照先unitごとに1行）と末尾の `export {名前};`（1行）で依存を宣言する。組立時に `tools/source-modules.mjs` がこの行だけを除くので、**配信はclassic scriptのままで実行時のESMではない。** 宣言と実コードの一致は `tools/check-module-graph.mjs` がbuild時に構文解析で検査し、未宣言の依存・未使用のimport/export・新しい未知の名前（綴り誤りを含む）・別unitの変数への新しい書込みを拒否する。

- 別unitの名前を使うときは両側の行を足す。行は1行のまま、宣言の本文へ `export` を付けない。
- `moduleGraph.ambient` はブラウザ標準と外部script提供名の台帳。増やすのは本当に新しい外部名のときだけ。
- `moduleGraph.crossUnitWrites` は別unitの変数へ書く既存の負債。増やさず、持ち主の関数を呼ぶ形にする。
- unitを直接動かすテストは `tools/test-source.mjs` の `sourceUnit()` で読む（行を除いた配信と同じ本文）。
