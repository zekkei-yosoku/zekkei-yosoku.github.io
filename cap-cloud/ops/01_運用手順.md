## 手動で再現する

作業場所は `/Users/okadayudai/Developer/Sorami/web`。Node.js（fetch/AbortSignal.timeout対応）とPython3＋NumPyを使用する。認証情報は不要。下記は運用担当者用で、一般利用者へ生ログを表示しない。

```sh

node cap-cloud/collect.mjs health data/cap-cloud-runs
```

取得が必要な時だけ一回実行する。

```sh

```

原応答・要求・スナップショット・実行記録を実行ごとのディレクトリへ新規作成する。過去ファイルを変更しない。下記のRUN_DIRECTORYと未使用の出力名は実際のパスに置き換える。

```sh
node cap-cloud/replay.mjs RUN_DIRECTORY data/新しい特徴量再計算.json
node cap-cloud/observations.mjs data/新しい特徴量再計算.json data/実観測.json data/新しい照合結果.json
python3 cap-cloud/model.py train data/新しい照合結果.json --train-end 2027-01-01T00:00:00+09:00 --cal-end 2027-04-01T00:00:00+09:00 --output data/新しい研究評価.json
```

分割日は書式例であり、収集実績に合わせて事前登録し直す。学習出力は既存ファイルも上書き可能なので未使用名を指定する。無観測の照合結果では学習を実行できない。見本の観測JSONは合成と明記してあり実データ照合を拒否する。

## 成功・注意・失敗への対応

| 結果 | 意味と次の操作 |
|---|---|
| success / healthy | 取得・保存・直近ファイル整合が正常。予報精度の合格ではない。観測を照合する |
| partial / warning | 特徴量不能の時刻がある、または直近収集が失敗。理由と件数を確認、過去入力を新規取得扱いにしない |
| attention | 成功履歴なし、最終取得から9時間超、未来の取得日時、ハッシュ不一致、未完了・壊れた記録。保存先・時計・収集停止を確認 |
| failed | 取得または保存失敗。HTTP本文、response-meta、manifestを確認。接続・容量・権限を修正してから別runへ再実行 |
| HTTP429 | 自動再試行しない。Retry-Afterと提供条件を確認し、待ってから必要な1回だけ実行。制限回避しない |
| HTTP400 | 要求の地点数・変数・単位を確認。9地点なら標高指定も9件。応答のエラーを正常値へ変換しない |

途中終了でmanifestがないディレクトリも点検対象。新しい成功runを作るだけではこの注意は消えない。原状を別の私用保管場所へ移して理由を記録してから再点検する。完全削除や元履歴の改ざんは行わない。

健全性は直近の成功／部分成功runのraw・snapshotハッシュを検証する。全履歴の完全な監査、OS停止中の通知、死活監視の外部サービスは未導入。必要なら運用開始時に監視担当と通知先を決める。

## 保管と復旧

原応答・時刻・source/raw/snapshotのハッシュ・ラベルの根拠をセットで保管する。コード変更時は旧原データから別名へ再計算する。再計算結果を新しい事前予報と呼ばない。実行環境のNode/Python/NumPy版も評価報告に記録する。

`web/data` は既存Git設定で無視される私用データ置き場。強制追加しない。リポジトリ公開時も画像・ラベル・予報履歴を同梱しない。自動削除なし。定期化前に実runのバイト数×4回/日×保管日数とバックアップ分で容量を見積もり、週1回に空き容量・破損・欠測率を点検する。バックアップ自体は未設定。

撤回するときはこのモジュールの実行を止める。定期化後なら登録を停止し、今回追加したcap-cloudとtest-cap-cloud.mjsを私用の99_oldへ移す。既存index.htmlやsorami-fuji.jsを過去コピーで戻さない。新設コードに依存する画面はないので、現在の表示に影響しない。

## 単画像の仮ラベルを整備する（2026-09-15）

画像はPillow使用。固定した日付・時刻集合を予報や発生結果を見る前に決める。次の例の日付と保存先は未取得の対象に置き換える。既存ディレクトリへの上書きは拒否する。

```sh
python3 cap-cloud/camera-images.py 2026-09-15 --max-images 15 --output data/cap-cloud-images-20260915
```

まだ来ていない時刻の画像や未掲載画像を推測しない。取得時点で存在する画像だけを原寸で確認し、出典・SHA256・公称時刻・理由・確認者・確認方法を記録する。AI仮ラベルの書式例は `data/cap-cloud-labels-20260915/AI仮ラベル.json`。画像別にNO_VISIBLE_CAP / VISIBLE_CAP / UNKNOWN / MOUNTAIN_OBSCURED。単方向のため全方向のcapPresentはnull。人が確認する場合も公称時刻の誤差と継続不明を残し、別版ファイルへ記録する。

```sh
node cap-cloud/image-labels.mjs data/cap-cloud-replay-v2.json data/cap-cloud-labels-20260915/AI仮ラベル.json data/新しい仮ラベル照合.json
```

証拠画像のハッシュを検証してから照合。`nominalTimeOverlap` が正でも正確な時刻一致ではなく、精度指標は返さない。人手監査・多方向・高頻度等が揃って初めて正式なobservations入力にする。正式入力ではreviewMethodが必須。AIの仮判定はUNKNOWN品質、人手確認済みを名乗らない。
